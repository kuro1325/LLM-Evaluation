# 大模型评测平台开发任务清单

## 阶段一：真实应用基础

- 将原型模拟状态改为真实评测状态机
- 增加 API Key 会话保存、掩码和验证
- 建立固定模型目录及 OpenRouter 元数据同步
- 抽离模型调用、Prompt、计分和类型模块
- 保留“演示模式”，方便无 Key 查看产品

验收：没有 API Key 时仍可体验演示；填写有效 Key 后可以进入真实模式。

## 阶段二：双模型调用

- 生成统一任务 Prompt
- 并行请求两个模型
- 增加 60 秒超时
- 记录完成耗时、Token、费用和错误
- 处理单边失败、双边失败及同模型拦截

验收：真实回答与客观指标可以稳定显示。

## 阶段三：裁判与计分

- 编写裁判 Prompt v1
- 定义并校验裁判 JSON
- 完成质量、效率、成本和权重计算
- 输出分项得分、证据、点评和推荐
- 权重调整后实时重算

验收：裁判不接收模型名称，最终分数不由裁判直接生成。

## 阶段四：反馈与校准

- 完成认可/不认可反馈对象
- 预留反馈上报接口
- 准备四类任务的少量校准案例
- 对比 AI 判断与人工反馈
- 修订裁判 Prompt 和规则版本

验收：能够定位不认可案例属于哪项规则偏差。

## 阶段五：交付

- 完成主流程和异常测试
- 检查 Key 与内容是否进入日志或持久化
- 更新 PRD、TRD 与使用说明
- 决定是否封装桌面端
